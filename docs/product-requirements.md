# Mosaic 万象集产品需求文档

## 1. 项目概述

### 1.1 产品名称

- 英文名：Mosaic
- 中文名：万象集
- 完整品牌名：Mosaic 万象集

### 1.2 产品口号

- 英文：Your AI team. From idea to full project delivery.
- 中文：你的云端 AI 团队，把一个想法生成一整套项目资产。

### 1.3 一句话定位

Mosaic 万象集是一个 **AI Workspace Agents 平台**，覆盖 Documents、Slides、Sheets、Images、Videos、Podcasts、Skypage、AI Developer 八大交付入口，并通过 Skill Hub 把专业能力包装成可复用技能，帮助用户把一个想法自动拆解成多个并行任务，生成一整套风格统一、可展示、可修改、可交付的项目资产。

### 1.4 核心判断

理解 Mosaic 需要三个视角同时在场：

**工具集合视角**：Mosaic 覆盖八大交付入口，每个入口对应一类专业产出形态——文档、幻灯片、表格、图片、视频、播客、网站页面、开发者代码。这不是"功能堆叠"，而是因为一个真实项目从来不是单一形态的输出。

**工作流视角**：入口之间通过项目工作流串联。一个典型路径是：调研（Documents + Sheets）→ 策略（Documents）→ 提案（Slides）→ 视觉方向（Images）→ 落地页（Skypage）→ 宣传视频（Videos）→ 播客内容（Podcasts）→ 多 Skill 并行产出。这是一个项目级交付流程，而不是多个独立工具的拼凑。

**用户心智视角**：Mosaic 不是 Chatbot，也不是工具箱。它是一支云端 AI 团队。用户不需要知道提示词怎么写，不需要在多个产品之间来回切换，只需要说清楚目标，系统负责拆解任务、并行执行、保证风格统一、输出可交付成果。

## 2. 背景与机会

### 2.1 用户现状

普通用户、小团队和服务商已经知道 AI 可以写文案、做 PPT、生成图片、写网页、做视频脚本，但他们仍然很难独立完成一个完整项目。

主要原因包括：

- 不知道如何把模糊想法拆成明确任务。
- 不知道每个阶段应该产出什么交付物。
- 需要在多个 AI 工具之间来回切换，内容上下文无法延续。
- 不同工具生成的内容风格不统一，最终拼凑感明显。
- 输出物往往只是草稿，不能直接给客户、老板、投资人或团队使用。
- 对 AI 不熟悉的用户，根本不知道从哪个工具开始。

### 2.2 市场机会

AI 产品正在从"问答工具"走向"项目执行系统"。下一阶段的机会不是让用户学习更多提示词，而是让用户用自然语言描述目标，然后获得完整项目成果。

**单点工具的天花板**：文档工具只解决写作，PPT 工具只解决演示，图片工具只解决视觉，视频工具只解决短片。用户的真实需求是"完整项目交付"，但没有任何单点工具能覆盖这个需求。

**项目级交付流程的空白**：目前市场上没有一款产品能把搜索调研、策略分析、文档输出、PPT 生成、图片创作、网站落地页、视频制作和播客内容串联成一个完整的项目工作流。

**降低项目启动门槛**：对普通用户的真正价值是——从"我不会用 AI"变成"我只要说清楚目标"。Mosaic 的机会在于切入**结果型 AI**：

- 用户购买的不是模型能力，而是项目结果。
- 用户需要的不是一个工具箱，而是一支可调用的 AI 项目团队。
- 商业场景天然需要多格式交付：报告、PPT、海报、落地页、社媒内容和视频脚本同时产出。

## 3. 目标用户

### 3.1 创业者

需要快速验证想法、包装项目、制作商业计划书、官网、路演材料和宣传内容。

### 3.2 中小商家

包括餐饮、美业、教培、健身、本地生活门店。核心需求是开业营销、活动推广、品牌升级、菜单视觉、社媒素材和落地页。

### 3.3 营销服务商

包括自由职业者、咨询顾问、代运营团队和小型营销公司。核心需求是快速为客户输出提案、方案、视觉方向和传播物料。

### 3.4 内容创作者

需要把一个选题扩展成图文、视频脚本、课程大纲、社媒矩阵和商业化页面。

### 3.5 企业市场团队

需要产品发布方案、活动方案、销售提案、内部汇报、官网内容和传播物料。

## 4. 产品目标

### 4.1 MVP 目标

第一版只聚焦一个核心目标：

> 用户输入一个项目想法后，Mosaic 能生成一套结构完整、风格统一、可以继续修改和展示的项目资产包。

### 4.2 成功标准

- 用户能在 5 分钟内创建一个项目。
- 系统能自动拆解不少于 6 个专业任务。
- 至少输出 5 类交付物，覆盖不少于 3 个不同入口。
- 所有交付物围绕同一份项目母版说明书生成。
- 用户可以在交付中心预览、修改和导出项目成果。
- 未验证的数据、市场判断和效果预估必须明确标注为"建议"或"推断"。

## 5. MVP 范围

### 5.1 首个场景

MVP 首个场景为：

> 门店开业营销项目包

适用行业包括：

- 餐饮
- 美业
- 健身
- 教培
- 本地生活服务

### 5.2 示例输入

用户输入：

> 我要在深圳开一家轻食餐厅，目标客户是附近白领和健身人群，希望做一套开业营销方案。

### 5.3 示例输出

系统通过多入口并行产出完整项目包：

1. 周边市场与竞品分析（Documents）
2. 品牌定位说明书（Documents）
3. 开业营销方案（Documents）
4. 客户展示 PPT（Slides）
5. 开业海报文案与视觉方向（Images）
6. 菜单结构与主推套餐（Sheets）
7. 小红书、朋友圈、抖音内容包（Documents）
8. 官网落地页（Skypage）
9. 30 秒宣传视频脚本（Videos）
10. 7 天开业执行清单（Sheets）

### 5.4 第一版暂不做

为了避免产品过早复杂化，MVP 暂不做：

- 真正的视频自动生成
- 高级图片编辑器
- 在线多人协作
- 企业审批流
- 自动广告投放
- 全行业模板覆盖
- 私有化部署
- 复杂 BI 数据看板
- Skill Hub 社区共享与自定义技能上传

## 6. 产品入口矩阵

Mosaic 通过八大入口覆盖项目交付的所有形态，每个入口对应一类专业产出，并由后端 Skill 层驱动生成。

### 6.1 Documents（文档）

- **用途**：输出调研报告、品牌策略、营销方案、竞品分析、执行手册、内容脚本等文字类交付物。
- **典型产出**：市场调研报告、品牌定位说明书、营销策略文档、内容创作脚本。
- **对应 Skill**：Research Skill、Strategy Skill、Copy Skill、Ops Skill。

### 6.2 Slides（幻灯片）

- **用途**：输出面向客户、投资人或内部团队的提案 PPT 和汇报文件。
- **典型产出**：客户提案 PPT、路演 Deck、活动方案汇报、项目进度汇报。
- **对应 Skill**：Deck Skill、Strategy Skill、Copy Skill。

### 6.3 Sheets（表格）

- **用途**：输出结构化数据，包括执行计划、预算表、竞品对比、内容排期和任务清单。
- **典型产出**：开业执行清单、竞品分析表、内容排期表、预算规划表。
- **对应 Skill**：Research Skill、Ops Skill、Strategy Skill。

### 6.4 Images（图片）

- **用途**：输出视觉方向、海报设计稿、社媒配图、菜单视觉和品牌素材。
- **典型产出**：开业海报视觉稿、品牌色彩与字体方向、菜单设计、小红书配图提示词。
- **对应 Skill**：Visual Skill、Copy Skill。

### 6.5 Videos（视频）

- **用途**：输出短视频脚本、分镜说明、字幕文案和视频策划书。
- **典型产出**：30 秒开业宣传视频脚本、抖音短视频策划、分镜描述、字幕文案。
- **对应 Skill**：Video Skill、Copy Skill。

### 6.6 Podcasts（播客）

- **用途**：输出播客节目大纲、访谈脚本、期节内容规划和文字稿。
- **典型产出**：品牌故事播客脚本、创业访谈大纲、内容系列规划。
- **对应 Skill**：Copy Skill、Strategy Skill。

### 6.7 Skypage（网站落地页）

- **用途**：输出可部署的网站落地页结构、页面文案和 HTML 代码。
- **典型产出**：品牌官网落地页、活动报名页、产品展示页、招商加盟页。
- **对应 Skill**：Web Skill、Copy Skill、Visual Skill。

### 6.8 AI Developer（开发者能力）

- **用途**：为有开发需求的用户提供代码生成、自动化脚本、API 集成方案和技术文档。
- **典型产出**：前端组件代码、API 对接方案、自动化工作流脚本、技术说明文档。
- **对应 Skill**：Dev Skill、Research Skill。

## 7. Skill Hub

Skill Hub 是 Mosaic 的能力中心，把专业技能包装成可复用的 Agent 模块，供项目工作流调用。

### 7.1 Skill Hub 定位

Skill Hub 不是功能列表，而是 Mosaic 的"专业团队成员库"。每个 Skill 是一个有明确职责、输入规范和产出格式的 AI Agent 模块。当项目工作流启动时，系统根据项目目标和所选入口，自动调度合适的 Skill 并行执行。

**两层架构**：
- 入口（Entry）：决定产出什么形态——文档、PPT、表格、图片、视频、播客、网站、代码。
- Skill（能力层）：决定用什么专业能力产出——调研、策略、文案、视觉、视频、网站、运营等。

一个项目可以同时触发多个 Skill 并行运行，每个 Skill 的输出汇入对应入口，最终在交付中心统一呈现。

### 7.2 内置核心 Skills

| Skill | 职责 | 主要服务的入口 |
| --- | --- | --- |
| Research Skill | 市场调研、竞品分析、客群洞察 | Documents、Sheets |
| Strategy Skill | 品牌定位、营销策略、项目主张 | Documents、Slides |
| Copy Skill | 宣传文案、社媒内容、活动话术 | Documents、Slides、Videos、Podcasts |
| Deck Skill | PPT 结构、页面文案、提案逻辑 | Slides |
| Visual Skill | 海报、菜单、社媒图的视觉方向与提示词 | Images、Skypage |
| Web Skill | 官网落地页结构与页面内容生成 | Skypage |
| Video Skill | 短视频脚本、分镜说明、字幕文案 | Videos |
| Ops Skill | 执行清单、时间节奏、落地动作 | Documents、Sheets |
| Dev Skill | 代码生成、API 集成、技术文档 | AI Developer |

### 7.3 Skill 结构

每个 Skill 包含以下核心属性：

- **输入规范（Input Schema）**：接受哪些项目上下文字段（项目目标、目标用户、行业、品牌风格等）。
- **产出格式（Output Type）**：输出到哪个入口，以什么格式呈现（Markdown、HTML、JSON、图片提示词等）。
- **适用场景（Use Cases）**：该 Skill 适合哪类项目类型和行业。
- **来源（Source）**：内置 Skill 或自定义 Skill。
- **状态（Status）**：可用、测试中、已停用。

### 7.4 并行调用机制

项目工作流启动后，系统按以下步骤调度 Skills：

1. 系统根据项目母版说明书确定所需 Skill 列表。
2. 无依赖关系的 Skills 并行执行，节省等待时间。
3. 有依赖关系的 Skills 按顺序执行（例如 Strategy Skill 需要 Research Skill 先完成）。
4. 每个 Skill 完成后，结果汇入对应入口的交付物列表。
5. 系统完成一致性检查后，生成最终交付中心。

### 7.5 Skill Hub 扩展方向（V1+ 规划）

- **社区 Skills**：允许高级用户或合作方发布自定义 Skill，供其他用户订阅调用。
- **行业专属 Skills**：为特定行业（餐饮、美业、教培、招商加盟等）定制垂直 Skill 包。
- **白标 Skills**：服务商可以在自有工作台中配置专属 Skill 组合。

## 8. 核心功能

### 8.1 项目创建

用户通过结构化表单创建项目，而不是从空白聊天框开始。

表单字段包括：

- 项目类型
- 行业
- 城市或目标市场
- 目标用户
- 项目目标
- 预算范围
- 品牌风格
- 已有素材
- 需要的交付物（按入口选择）

### 8.2 项目母版说明书

系统先生成一份"项目母版说明书"，作为所有后续交付物的统一依据，确保跨入口内容风格一致。

内容包括：

- 项目目标
- 目标用户
- 核心卖点
- 品牌语气
- 视觉风格
- 内容主张
- 交付物清单（按入口组织）
- 禁用方向
- 未验证假设

### 8.3 入口 + Skill 双层编排

系统根据项目母版说明书，执行两层编排：

**第一层：入口编排**——根据用户选择的交付物确定需要激活哪些入口（Documents、Slides、Sheets、Images、Videos、Podcasts、Skypage、AI Developer）。

**第二层：Skill 编排**——根据每个激活的入口，从 Skill Hub 调度对应的专业 Skill，并行执行。

入口与 Skill 的映射关系：

| 激活入口 | 调用 Skill |
| --- | --- |
| Documents | Research Skill、Strategy Skill、Copy Skill、Ops Skill |
| Slides | Deck Skill、Strategy Skill、Copy Skill |
| Sheets | Research Skill、Ops Skill |
| Images | Visual Skill、Copy Skill |
| Videos | Video Skill、Copy Skill |
| Podcasts | Copy Skill、Strategy Skill |
| Skypage | Web Skill、Copy Skill、Visual Skill |
| AI Developer | Dev Skill、Research Skill |

### 8.4 项目工作台

项目工作台展示 AI 团队的执行过程，让用户始终知道系统在做什么。

核心信息包括：

- 项目目标
- 项目母版说明书
- 任务拆解清单
- 各入口的激活状态
- 各 Skill 执行状态
- 当前产出物
- 需要用户确认的问题

任务状态包括：

- 等待中
- 生成中
- 已完成
- 需要修改
- 生成失败

### 8.5 交付中心

交付中心是用户最终查看成果的地方，按入口分类展示所有交付物，不展示为聊天记录。

交付中心包括：

- 项目总览
- 按入口分类的交付物列表
- 每个交付物的预览
- 修改入口
- 重新生成入口
- 导出入口
- 分享链接
- 版本记录

MVP 导出格式优先支持：

- Markdown
- HTML
- PPT 大纲
- 图片生成提示词
- 视频脚本
- 项目打包下载

## 9. 用户流程

### 9.1 创建项目流程

1. 用户进入 Workspace 首页。
2. 点击"创建项目"或从模板库选择。
3. 选择"门店开业营销项目包"。
4. 填写行业、城市、目标用户、预算、风格和素材。
5. 选择需要的交付物（按入口选择）。
6. 提交生成。

### 9.2 AI 执行流程

1. 系统生成项目母版说明书。
2. 系统根据说明书确定激活入口与所需 Skill。
3. 系统按依赖关系编排 Skill 执行顺序，无依赖的并行执行。
4. 各 Skill 结果汇入对应入口的交付物。
5. 系统检查跨入口的内容口径和风格一致性。
6. 生成项目交付中心。

### 9.3 用户修改流程

1. 用户进入交付中心。
2. 选择某个入口下的交付物。
3. 输入修改意见。
4. 系统基于项目母版说明书重新生成该交付物。
5. 用户保存新版本。

## 10. 页面规划

### 10.1 Workspace 首页

Workspace 首页的核心任务是让用户理解 Mosaic 的"云端 AI 团队"价值，并快速开始项目。

核心内容：

- 品牌主张（云端 AI 团队 / 完整项目交付）
- 创建项目入口
- 八大入口入口区（直观展示可交付的内容形态）
- 项目模板入口
- 示例项目入口
- 我的项目入口

首页主文案：

> Your AI team. From idea to full project delivery.
>
> 你的云端 AI 团队，把一个想法生成一整套项目资产。

### 10.2 八大入口区

Workspace 首页展示八大入口模块，每个入口模块包括：

- 入口名称与图标
- 一句话说明用途
- 快捷创建按钮（可独立从该入口开始）
- 展示该入口的典型产出示例

入口排列顺序（推荐展示顺序）：

1. Documents
2. Slides
3. Sheets
4. Images
5. Videos
6. Podcasts
7. Skypage
8. AI Developer

### 10.3 项目创建页

页面以结构化表单为主，降低用户输入压力。

核心模块：

- 项目类型选择
- 基础信息填写
- 交付物选择（按入口分组）
- 素材上传
- 生成前确认

### 10.4 项目工作台

工作台展示 AI 项目团队正在做什么。

核心模块：

- 项目摘要
- 项目母版说明书
- 入口激活状态
- Skill 执行状态
- 当前成果
- 用户确认区

### 10.5 交付中心

交付中心用于承载最终成品，按入口分类展示。

核心模块：

- 项目资产列表（按入口分组）
- 成果预览
- 修改和重生成
- 导出
- 分享

### 10.6 Skill Hub 页面

Skill Hub 页面让用户了解系统使用了哪些专业技能，以及未来可用的扩展技能。

核心模块：

- 内置 Skill 列表（名称、职责说明、服务的入口）
- Skill 使用记录（本次项目调用了哪些 Skill）
- Skill 状态（可用、测试中、维护中）
- 自定义 Skill 入口（V1+ 规划，MVP 阶段展示占位）

## 11. 数据结构草案

### 11.1 Project

项目对象包括：

- id
- name
- type
- industry
- market
- target_audience
- goal

## 12. 质量控制

### 12.1 一致性检查

系统在生成交付中心前，需要跨入口检查：

- 品牌名称是否一致
- 目标用户是否一致
- 核心卖点是否一致
- 文案语气是否一致
- 视觉方向是否一致
- 不同入口的交付物是否相互冲突

### 12.2 事实与风险标注

所有未经验证的信息必须标注来源或状态。

示例：

- "基于用户输入推断"
- "建议进一步验证"
- "需要线下调研确认"
- "非真实经营数据"

### 12.3 敏感信息保护

系统不得在日志、导出物或错误信息中暴露：

- API Key
- Token
- 密码
- 私钥
- Cookie
- Session
- 数据库连接串
- 用户隐私数据

涉及第三方 API 的密钥只能从服务端安全环境变量读取，不得进入前端代码或可被浏览器访问的位置。

## 15. 竞争定位

### 15.1 与 ChatGPT / Claude 的区别

ChatGPT 和 Claude 是对话助手，用户需要自己拆解任务、管理上下文、复制粘贴到其他工具。Mosaic 是项目交付系统，用户只需说清楚目标，系统自动拆解、并行执行、多入口产出、保证风格统一。

### 15.2 与单点 PPT 工具的区别

PPT 工具只解决演示文件一个形态。Mosaic 在生成 PPT 的同时，还产出调研文档、竞品分析表格、视觉方向、落地页和视频脚本，是完整项目交付，不是单一文件生成。

### 15.3 与设计工具的区别

设计工具解决视觉制作，用户仍需自己定义项目目标和品牌策略。Mosaic 先产出品牌定位和营销主张，再驱动视觉方向生成，策略和视觉是同一个工作流的两个阶段。

### 15.4 与 Skywork 的区别

Skywork 是重要标杆，在项目交付方向有先发优势。Mosaic 的差异化方向是：更聚焦中文商业场景、本地服务业和营销项目交付；通过 Skill Hub 实现能力的模块化和可复用；八大入口矩阵覆盖更完整的项目交付形态；并提供面向服务商的白标工作台。

### 15.5 与 Notion AI / 飞书妙记的区别

这类工具是文档工具的 AI 增强，核心仍然是单一文档场景。Mosaic 是以项目为单位的多入口并行交付，本质上是不同的产品形态。

## 16. 产品原则

1. 项目优先，不是聊天优先。
2. 结果优先，不是工具优先。
3. 场景优先，不是功能堆叠。
4. 统一性优先，不是单点惊艳。
5. 可交付优先，不是演示优先。
6. 简单优先，第一版只做闭环最短路径。
7. 入口为表面，Skill 为能力，项目为单位——三层分离，各司其职。

## 17. 开放问题

以下问题不阻塞 MVP，但需要在进入研发前继续确认：

- 第一版是否需要真实联网搜索，还是先使用用户输入和静态模板生成？
- PPT 第一版输出 PPTX 文件，还是先输出 PPT 大纲和 HTML 预览？
- 图片第一版生成真实图片，还是先生成视觉方向和图片提示词？
- 项目包导出第一版是 ZIP，还是先提供单文件下载？
- 是否需要在第一版接入支付？
- Skill Hub 第一版是否只展示内置 Skill，不开放自定义入口？
- AI Developer 入口第一版优先支持哪类代码产出（前端页面、API 文档、自动化脚本）？

## 18. 最终愿景

Mosaic 万象集最终不是一个 AI 工具箱，而是下一代项目生产系统。

未来用户不再说：

> 帮我写一篇文章。
>
> 帮我做一个 PPT。
>
> 帮我生成一张海报。

而是说：

> 帮我启动一个品牌。
>
> 帮我开一家店。
>
> 帮我做一次发布会。
>
> 帮我给客户交付一套方案。
>
> 帮我把这个想法变成完整项目资产。

Mosaic 的长期价值，是让一个普通人、小团队或服务商，通过云端 AI 团队和可复用 Skill Hub，用 AI 拥有过去一个完整项目团队的能力——调研员、策略师、文案、设计师、开发者、运营专员，全部在线，随时调用。
